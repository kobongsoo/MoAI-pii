 *   Windows: moaipii.dll   Linux: libmoaipii.so
 * 규칙은 docparse.h 와 같다:
 *   - char** out 으로 받은 문자열은 성공이든 실패든 moaipii_free 로 돌려준다(C free 금지).
 *   - const char* 로 받는 것(버전)은 고정 문자열이라 해제하지 않는다.
 *   - 성공·실패는 반환 코드로 가르고, 사유는 결과 JSON 의 "error" 에 있다.
 *   - 전역 상태가 없어 여러 스레드에서 동시에 불러도 된다.
 */
#define MOAIPII_ABI_VERSION 1

typedef enum { MP_OK = 0, MP_ERR_ARG = 1, MP_ERR_UTF8 = 2, MP_ERR_FAILED = 5, MP_ERR_PANIC = 99 } mp_status;

uint32_t    moaipii_abi_version(void);
const char* moaipii_version(void);              // "0.1.0+abc1234"
const char* moaipii_kopii_basis(void);          // "1.15.2" — 어느 ko-pii 를 보고 옮겼나(지금의 KOPII_PORTED_FROM)
int         moaipii_labels(char** out_json);      // 지원 라벨·별칭 목록 (UI 규칙 편집기가 씀)
int         moaipii_scan(const uint8_t* text, size_t len,
                         const char* opts_json, char** out_json);
void        moaipii_free(char* p);                 // 지우기 전에 0 으로 덮는다

4-2. 안전 규칙

규칙왜
본문은 (포인터, 길이)로 넘긴다 — 널 종료 문자열이 아니다추출된 본문에는 \x00이 섞일 수 있다. 널 종료로 받으면 그 뒤가 소리 없이 잘려 미탐이 된다. docparse는 경로만 받아서 이 문제가 없었다.
좌표 단위는 부르는 쪽이 고른다 — 기본은 문자(코드포인트)언어마다 문자열을 세는 단위가 다르다. Python str은 코드포인트, Java String은 UTF-16, PHP·C++ 문자열은 바이트다. 감싸개가 자기 언어에 맞는 단위를 요청하면 substring·substr로 바로 자를 수 있다(§5-2). 기본값 char는 지금 pii_records가 내보내는 기준(to_char_offsets, 2026-09-11)과 같다. invalid_utf8:"replace"일 때 byte 좌표는 넘긴 원래 바이트를 가리키도록 라이브러리가 되돌려 맞춘다.
Python은 encode("utf-8", "replace")로 넘긴다본문에 짝 없는 서로게이트가 있으면 엄격한 인코딩은 실패한다. replace는 한 글자를 ? 한 글자로 바꾸므로 글자 수가 1:1로 유지되어 좌표가 그대로 맞는다.
원문 값은 기본으로 싣지 않는다"값은 세자마자 버린다"는 프라이버시 원칙. Python은 좌표로 text[start:end]를 직접 잘라 쓰므로 values가 필요 없다. Rust 판의 --with-pii만 values:true를 쓴다.
moaipii_free는 0으로 덮고 지운다결과 JSON에 위치나 값이 있으면 해제된 메모리에 남지 않게 한다.
패닉은 경계에서 잡는다 (catch_unwind, panic = "unwind")docparse와 같다. 문서 하나 때문에 데몬 전체가 죽지 않게 한다.
"오늘 날짜"를 옵션으로 받는다지금 TODAY는 프로세스가 처음 쓸 때 한 번만 정해진다. 그래서 며칠씩 도는 데몬은 날짜가 낡는다. 라이브러리에서는 호출마다 계산하고, 시험에서는 today로 고정할 수 있게 한다(결정적 골든).
로그 콜백 없음검출기는 로그를 남기지 않는다. 남기면 개인정보가 로그로 샐 수 있다. docparse의 set_logger는 넣지 않는다.

4-3. 버전 관리

  • MOAIPII_ABI_VERSION — 함수 이름이나 인자 모양이 바뀔 때만 올린다. 감싸개는 불러온 직후 비교하고, 다르면 로드를 거부한다.
  • moaipii_version() — 0.1.0+<git해시>. MpowerClassify --version은 (moaipii 0.1.0+abc1234, ko-pii 기준 1.15.2)로 바꾼다. 지금은 Python이 "ko-pii 1.15.2", Rust가 "ko-pii 포팅 기준 1.15.2"로 서로 다르게 찍는다.
  • CHANGELOG.md에는 "결과 바뀜" 표시를 단다. 그 표시가 있는 판을 받으면 MpowerClassify 평가셋을 다시 돌린다.

언어별 감싸개 — Python · Rust · Java · PHP · C++

C 진입점은 하나이고, 언어마다 얇은 감싸개를 둔다. 감싸개가 하는 일은 다섯 언어 모두 같다. 라이브러리 찾기 → ABI 확인 → 본문을 UTF-8 바이트로 넘기기 → 결과 JSON 읽기 → 곧바로 moaipii_free → 언어의 예외로 바꾸기. Java·PHP 감싸개는 DocParse-rust의 bindings/java(JNA)와 bindings/php(FFI) 틀을 그대로 따른다.

5-2. 좌표 단위를 언어마다 다르게 받는 이유

같은 본문이라도 "몇 번째"를 세는 단위가 언어마다 다르다. 감싸개가 자기 언어의 단위로 받아야 그 언어의 기본 자르기 함수로 바로 마스킹할 수 있다. 단위를 잘못 맞추면 오류 없이 엉뚱한 자리를 지운다(2026-09-11 Rust 판에서 실제로 일어난 일).

// 본문: "홍길동 😀 010-1234-5678"   ← 이모지는 코드포인트 1개 = UTF-16 2개 = UTF-8 4바이트
offsets   start  end   그 언어에서 자르기
char        6     19   Python  text[6:19]
utf16       7     20   Java    text.substring(7, 20)
byte       15     28   PHP     substr($text, 15, 13)   ·  C++  text.substr(15, 13)

PHP에서 mb_substr를 쓰고 싶으면 offsets:"char"를 주면 된다. 감싸개 기본값만 위 표대로 둔다.

5-3. 같은 이름의 API

언어 관례(대소문자)만 다르고 이름과 뜻은 같다. 문서와 시험을 한 벌로 쓰기 위해서다.

5-4. 언어별 주의

언어주의정한 방법
JavaJNA에는 size_t 형이 없다배포 대상이 x64 두 개뿐이므로 long으로 받는다. 감싸개가 불러올 때 Native.SIZE_T_SIZE == 8을 확인한다
Java짝 없는 서로게이트getBytes(UTF_8)가 ? 한 글자로 바꾼다. UTF-16 한 칸이 한 칸으로 남으므로 utf16 좌표가 맞는다
Java본문 사본byte[]를 바로 넘긴다(JNA가 고정해 넘김). 호출 뒤 그 배열을 Arrays.fill(0)로 지운다
PHPFFI가 켜져 있어야 한다CLI는 기본 설정으로 된다. 웹(php-fpm·Apache)은 ffi.enable=true 또는 opcache.preload가 필요하다. 연동설명서에 적는다(DocParse와 같은 안내)
PHPPHP 문자열은 UTF-8이 아닐 수 있다(EUC-KR 등)감싸개 기본값을 invalid_utf8:"replace"로 둔다. byte 좌표는 원래 바이트를 가리키므로 substr가 그대로 맞는다. EUC-KR 본문은 부르는 쪽이 먼저 mb_convert_encoding으로 바꾸라고 설명서에 적는다
PHPcdef는 전처리기를 못 읽는다docparse처럼 moaipii.h의 선언만 감싸개 안에 옮겨 둔다. 헤더가 바뀌면 함께 고치고, 공통 시험이 이를 잡는다
C++링크형과 동적 로드형기본은 링크형이다(Windows moaipii.dll.lib, Linux -lmoaipii -Wl,-rpath,'$ORIGIN'). #define MOAIPII_DYNAMIC이면 LoadLibraryW/dlopen으로 실행 중에 찾는다. 다른 언어 감싸개와 같은 동작이다
C++메모리 해제std::unique_ptr<char, FreeFn>로 받아 예외가 나도 moaipii_free가 불린다
C++JSON 해석기외부 의존을 없애려고 결과 모양(counts 객체, items 배열)만 읽는 작은 해석기를 헤더에 넣는다. 일반 JSON은 scanJson으로 원문을 넘긴다
전부스레드라이브러리에 전역 상태가 없으므로 감싸개 객체 하나를 여러 스레드가 함께 써도 된다. 불러오기만 한 번(Java static·C++ 함수 내부 static·PHP 요청당 한 번)

5-5. 공통 시험 — 다섯 감싸개가 같은 답을 내는가

tests/bindings/cases.json에 사례와 정답을 한 번만 적는다. 언어별 실행기 다섯 개가 같은 파일을 읽어 결과를 정해진 모양의 JSON으로 내고, tests/bindings/run_all.sh가 정답과 비교한다. 본문은 NUL·깨진 UTF-8을 담을 수 있도록 base64로 적는다.

사례지키는 것

13-1. 설계와 달라진 점

  • 골든 자료 위치 — 저장소 tests/가 아니라 crates/moaipii/tests/에 두었다. 빌드서버에 crates/만 올려도 골든 시험이 돌게 하려는 것이다.
  • 옵션 unknown_labels — 기본은 error다. MpowerClassify 두 판은 예전 Rust 판처럼 모르는 라벨을 0건으로 보도록 ignore를 쓴다. Python 판은 그 라벨을 처음 볼 때 한 번 경고로 남긴다.
  • MpowerClassify Rust 판 — pii.rs를 지우지 않고 라이브러리 창구로 바꿨다(pii_counts·pii_records 이름 유지). 그래서 rules.rs는 한 줄도 바뀌지 않았다. --moaipii-lib 인자와 CSO_MOAIPII 환경변수를 두고, 규칙셋에 PII 규칙이 있으면 문서를 읽기 전에 라이브러리를 불러 본다.
  • C++ 헤더 정본은 bindings/cpp/moaipii.hpp에 두고, 묶음에서는 include/로 들어간다.

13-2. 남은 일

  • MoAI-pii 첫 커밋 → 버전에 git 해시가 붙은 묶음으로 다시 빌드 → update-moaipii.sh

  • PHP 감싸개 실제 시험(PHP 7.4+ FFI가 있는 곳)
  • 7단계 측정(평가셋 2개 · 분류함 · V10 비교) → 8단계 Python 기본값 전환 · ko-pii 삭제 · ui/rulesedit.kopii_labels를 moaipii_labels로
